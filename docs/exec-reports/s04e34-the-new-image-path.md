## The pitch

S04E33 built the means to copy a published image to the new registry path without rebuilding it. This episode runs it, checks the result from outside,
points the documentation at the new path, and fixes the verification instructions. That last part is a mistake of mine from S04E31.

## Scene-by-scene

### Act I -- Run it, then do not believe it

The `mirror-image` workflow was dispatched from `main`. It succeeded and its own read-back reported all four tags at the original digest, which is the
script grading itself. So the result was checked from outside, with no credentials at all:

- **Public, anonymously.** A new package can default to private, which would have made it useless; all four tags answer HTTP 200 to an anonymous pull token,
  and the tag list is `2.4.0, 2.4, 2, latest`.
- **Same bytes.** `sha256:3487d68a...` on both paths, read independently.
- **It runs.** A fresh pull of the new path reports `hopper 2.4.0`.
- **Provenance follows the image.** `gh attestation verify oci://ghcr.io/schwartzkamel/hopper:2.4.0 --owner SchwartzKamel` verifies, and it is the original
  attestation: signed by `release.yml@refs/tags/v2.4.0`, recording the old repository as the source. Nothing was re-attested.

### Act II -- Not a blanket replace

About 70 references name the old image path, and a global replace would have been wrong: the path has real history. Tags such as `1.8.1` and `2.0.5`,
and the `/az-ai` and `/az-ai-v2` sub-paths, exist only at the old locations. Only references to the **current** image moved: the README's `docker pull` and
`run`, the Dockerfile's usage comment, the verification table, and the release runbook. The old path is described, not erased: a dated section in
`ghcr-tag-policy.md`, a row in the lifecycle table, and one plain sentence in the README. The old path is **frozen at v2.4.0 and stays available at least
until the next major version**, the same review point as the `az-ai` alias.

### Act III -- My mistake

The S04E31 sweep rewrote the old repository slug to the new one across 51 files, mechanically. Seven of those were `gh attestation verify ... --repo
SchwartzKamel/azure-openai-cli` instructions, now `--repo SchwartzKamel/hopper`. S04E31 recorded, correctly, that `--repo` with the new name **fails**
for every release up to v2.4.0, because their attestations name the old repository. It did not connect that fact to the seven lines it had just rewritten.
So for a day, `SECURITY.md` and the verification guide told anyone checking a release to run a command that fails.

All seven now say `--owner SchwartzKamel`, which verifies old and new releases alike, and the two documents people read first say why. A guard now scans every
tracked file outside the history directories for a `gh attestation verify` command, including its continuation lines, carrying `--repo SchwartzKamel/hopper`.
Four mutations, including one that puts the flag on a later continuation line, are caught.

### Act IV -- Correct the public body

The published v2.4.0 release body still pointed at the old image path and said no package manager install existed. It was regenerated by the tested script from
the release's real digests. The diff was read before applying: only the image path and the package-manager section changed, the release notes are
byte-identical, and the 13 assets have the same names and sizes before and after. The manifests' digests still match.

## What shipped

- The mirror was run, and verified from outside. The README, Dockerfile, verification guide, runbooks, SECURITY.md and the tag policy now describe the current
  image path and the right verification flag; the published release body is corrected.
- 3 integration cases for the guard. **Mutation-checked:** 5 mutations (the flag on one line, on a continuation line, the note removed, the README reverted), each caught.
- ADR-016 updated, CHANGELOG, the findings backlog and this report.

**Not changed, on purpose**

- Migration and rollback documents, and the references to images that exist only at the old paths (`1.8.1`, `2.0.5`, `/az-ai-v2`): they describe the past.
- Nothing was re-attested, and no archive or asset was touched.

## Lessons from this episode

1. **A mechanical sweep needs semantic exclusions.** The string was the same; the meaning was not. Verification instructions are not addresses.
2. **When you record that a thing is broken, search for what you just changed that depends on it.** I wrote the fact down and did not look.
3. **Verify the mirror from outside, anonymously.** The script's own read-back is not evidence of what a user sees.
4. **Edit the public body, then prove the assets did not move.** Same names, same sizes, same digests.
5. **Describe the past; do not rewrite it.** Old paths stay named in the documents that are about them.
