# CONTEXT -- domain glossary (ubiquitous language)

## Terms

| Term | Means | Canonical name (code / UI) | Not to be confused with |
|---|---|---|---|
| **JSON Response Envelope** | The single structured JSON document emitted on stdout when `--json` is passed on a chat/agent/ralph completion (`response`, `model`, `mode`, `input_tokens`, `output_tokens`, `total_tokens`, `duration_ms`, `cached`). | `ChatJsonResponse` | `ErrorJsonResponse` (emitted on stderr when an invocation fails) |
| **Code Extraction Mode** | CLI flag `--code` that strips markdown prose and fences from the model response and writes only extracted code blocks to stdout. | `Opts.Code` / `ExtractCodeBlocks` | `--raw` (which emits the entire model response verbatim without spinner/trailing newline) |
| **Combined Stdin Prompt** | Merging piped `stdin` content with a positional CLI prompt (`cat file | az-ai "explain"`) into a single prompt payload with`<context>` framing. | `MergeStdinAndPrompt` | Stdin-only prompt (`echo "hi" | az-ai`) |
| **Manifest Tool (Plugin)** | An external executable tool defined by a JSON manifest (`*.json`) in `~/.config/azureopenai-cli/tools/` or `./.azureopenai-cli/tools/` and exposed as an `AITool`. | `ToolManifest` / `ManifestTool` | Built-in tools (`shell_exec`, `read_file`, `web_fetch`, `get_clipboard`, `get_datetime`, `delegate_task`) |
| **Tool Introspection** | CLI flag `--list-tools` (optionally with `--json`) that enumerates all active built-in and manifest tools, their source (`builtin` vs `user-plugin` vs `local-plugin`), and descriptions. | `ListToolsCommand` / `ToolDescriptor` | `--tools` (which filters which tools are enabled for an agent run) |
| **MCP Stdio Server** | Subcommand `az-ai mcp serve` (or `--mcp-serve`) that speaks JSON-RPC 2.0 over stdin/stdout (`initialize`, `tools/list`, `tools/call`, `ping`) so external agents can invoke `az-ai` tools. | `McpStdioServer` | MCP client (calling external MCP servers) |
| **Shared Transport Handler** | A process-wide `SocketsHttpHandler` shared between `PrewarmAsync` and `AzureOpenAIClient` via `HttpClientPipelineTransport` so TLS prewarming warms the actual connection pool used by chat completions. | `GetSharedHttpClient` / `SharedSocketsHandler` | Disposable throwaway `HttpClient` |

| **Pattern Library** | Built-in and user-defined (`~/.config/azureopenai-cli/patterns/*.json`) reusable system-prompt templates (`summarize`, `fix-grammar`, `commit-message`, `explain-code`, `shell-oneliner`, `json-extract`, `code-review`, `security-audit`) applied via `--pattern <name>` / `-p <name>` and listed via `--patterns [--json]`. | `PatternTemplate` / `PatternRegistry` | `PersonaConfig` (which is a stateful `.squad/` agent with memory and tools) |
| **NDJSON Streaming (`--jsonl`)** | CLI flag `--jsonl` that emits one compact JSON line per streaming event (`delta`, `tool_call`, `done`, `error`) so external tools and parent agents can consume live token streams without buffering. | `Opts.Jsonl` / `JsonlStreamEvent` | `--json` (which emits a single buffered `ChatJsonResponse` object at completion) |
| **MCP Stdio Client (`--mcp-server`)** | Outbound stdio JSON-RPC 2.0 client (`McpStdioClient`) that connects to external MCP servers (`--mcp-server <name>=<command>` or `az-ai mcp call`), discovers their tools via `tools/list`, and registers them as `AITool` instances inside `az-ai`'s agent/Ralph loop. | `McpStdioClient` / `McpClientAIFunction` | `McpStdioServer` (`az-ai mcp serve`, where `az-ai` acts as the server) |
| **MCP Prompts & Resources** | MCP server protocol methods `prompts/list`, `prompts/get` (exposing `PatternRegistry` patterns and `.squad.json` personas) and `resources/list`, `resources/read` (exposing `.squad.json` and `.squad/history/*.md`) over `az-ai mcp serve`. | `McpPromptsListResult` / `McpResourcesListResult` | `tools/list` / `tools/call` |
| **Provider Adapter (`--provider`)** | Multi-provider chat client router supporting `azure` (default), `openai`, `openrouter`, `ollama`, `llamacpp` (`local`), and `custom` OpenAI-compatible endpoints using the in-tree `OpenAIClient` + `SharedHttpClient` with loopback-only `http://` relaxation for local models. | `ProviderSelector` / `ProviderDescriptor` | `UserConfig.ResolveModel` |
| **Commander Work Queue (`az-ai queue` / `az-ai commander`)** | Built-in DAG-aware persistent task queue (`.az-ai/queue.json`) supporting `init`, `add`, `list`, `status`, `plan`, `run` (`--concurrency`, `--dry-run`, `--recover-stale`), and `clear`, with per-task provider, model, persona, pattern, and validation command routing. | `WorkQueue` / `CommanderRunner` / `QueueTaskItem` | `RalphWorkflow` (which loops on a single task) |

- "Plugin DLL" -> use **Manifest Tool (Plugin)** (AOT binaries use JSON-manifest subprocess tools, never `.dll` reflection loading).
- "JSON error on stdout" -> use **`ErrorJsonResponse` on stderr** (happy-path `ChatJsonResponse` goes to stdout; errors go to stderr).
